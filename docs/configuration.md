# Настройки Curse-Cycle

[Документация](README.md) · [Правила игры](../README.md) · [Команды](commands.md)

Конфигурация находится в `config/cursecycle.json` в папке экземпляра игры или выделенного сервера. Она создаётся при первом запуске. В CurseForge используйте папку конкретного профиля.

## Расписание

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `challengeIntervalDays` | `5` | Период смены испытаний в игровых днях, можно дробный; от 1/24 000 до 2 147 483 647 дней |
| `noticeLeadTimeDays` | `1` | За сколько игровых дней до смены выбирается следующее испытание: от 0 до длительности, можно дробное значение |
| `initialPreparationSeconds` | `60` | Подготовка перед первым колесом, целое число секунд от 0 |

Один игровой день — 24 000 тиков времени мира. Дробные значения округляются до ближайшего тика: 2.5 дня — 60 000 тиков, 0.5 дня — 12 000 тиков. Сон и команды изменения времени приближают или отдаляют срок обычной смены. Реальные часы при выключенном сервере не используются.

Подготовка и первое колесо используют серверные тики при наличии игроков: 20 тиков соответствуют секунде при 20 TPS. Первое колесо длится 100 тиков; отключение его анимации на клиенте этот серверный срок не меняет. Без игроков подготовка и первое колесо приостанавливаются.

При `noticeLeadTimeDays: 0` заранее анонсировать нечего: новое испытание выбирается при смене. Если предупреждение равно длительности, следующее выбирается уже в начале периода. Колесо не сбрасывает отсчёт и не завершает текущие правила.

Пример фрагмента конфигурации для смены каждые 2.5 дня с предупреждением за 0.5 дня; остальные поля существующего файла сохраните:

```json
{
  "challengeIntervalDays": 2.5,
  "noticeLeadTimeDays": 0.5,
  "initialPreparationSeconds": 60
}
```

### Изменение в меню

Откройте **H → Настройки**, измените значения и нажмите «Применить». Владелец одиночного мира может менять расписание без читов; на сервере нужен OP 2. Сервер проверяет права, значения и сохранение файла.

В полях дней меню принимает точку и запятую (`2.5` или `2,5`). В JSON используйте точку. Для изменения расписания через меню клиент и сервер должны поддерживать дробные дни.

- Изменение длительности начинает новый интервал от текущего времени мира. Активные испытания, история и уже выбранное следующее сохраняются.
- Изменение только предупреждения не запускает интервал заново.
- Новая длительность подготовки применяется к ещё не начавшемуся первому колесу; уже начавшуюся прокрутку она не перезапускает.
- Настройки сохраняются для этой установки/сервера и используются также в других его мирах. Прогресс и история каждого мира независимы.

При ручном редактировании JSON закройте игру или остановите сервер, измените файл и запустите заново. Отдельной команды перезагрузки конфигурации нет. Правило перезапуска отсчёта выше относится к применению через меню; редактирование файла не выполняет этот обработчик.

## Сложности и заполнение колеса

`difficultyWeightsByDay` задаёт этапы по номеру дня мира. Используется этап с наибольшим порогом, который уже наступил. Три числа — желаемое количество лёгких, средних и сложных секторов:

```json
{
  "difficultyWeightsByDay": {
    "1": [3, 2, 1],
    "20": [2, 3, 2],
    "50": [1, 2, 3]
  }
}
```

Число секторов равно сумме трёх значений. Победитель выбирается случайно среди секторов. Когда нужной сложности не хватает, недостающие места занимают оставшиеся испытания других сложностей, в том числе сложности с нулевым весом. Нулевой вес не отключает испытание — для этого используется `challengeToggles`.

Разные кандидаты используются до повторов секторов. Уже выбранный победитель удаляется из общего пула, а весь пул пополняется после исчерпания. От появления испытания только в качестве сектора оно из пула не удаляется.

Ключ этапа должен быть целым числом от 1; значения — ровно три неотрицательных целых числа с ненулевой суммой. Некорректные этапы отбрасываются; если не осталось ни одного, восстанавливаются стандартные этапы.

## Включение испытаний

`challengeToggles` связывает ID из [списка испытаний](challenges.md) с `true` или `false`:

```json
{
  "challengeToggles": {
    "the_floor_is_lava": false,
    "heavy_body": true,
    "test_easy": false
  }
}
```

Обычные испытания и двойное включены, если ID не указан. Шесть `test_*` заглушек отключены по умолчанию, в том числе для старых конфигураций с пустой картой. Для отладки они включаются только явным `true`.

Отключённые ID исключаются из выбора и отфильтровываются из сохранённой активности при обработке расписания. Если начатый цикл пуст, система пытается включить доступное испытание сразу. Для продолжения цикла должно оставаться хотя бы одно доступное обычное испытание: одно двойное без компонентов не создаёт игровых правил.

## Интерфейс и звуки

Эти параметры читаются на клиенте. Меню позволяет менять HUD и анимацию; ID звуков редактируются в JSON.

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `enableHudOverlay` | `true` | Показывать панель Curse-Cycle; F1 также её скрывает |
| `hudScalePercent` | `100` | Масштаб плашки испытаний: от 50 до 100%; меняется в H → Настройки кнопками −/+ с шагом 10% и сохраняется сразу |
| `hudPositionX` / `hudPositionY` | `10` / `10` | Координаты панели в единицах GUI; отрисовка ограничивается видимой областью |
| `enableWheelAnimation` | `true` | Показывать анимацию и воспроизводить звуки колеса |
| `wheelSoundPath` | `minecraft:block.amethyst_block.hit` | Звук при прохождении секторов |
| `wheelFinishSoundPath` | `minecraft:block.respawn_anchor.charge` | Звук завершения колеса |

HUD испытаний, полоса heartbeat и выносливость автоматически уменьшаются, если доступная
область GUI меньше 640×360 единиц, в том числе при большом размере интерфейса Minecraft.
`hudScalePercent` дополнительно уменьшает общую плашку испытаний относительно этого размера.
Полосы heartbeat и выносливости остаются над хотбаром и шкалами Minecraft.

`maxActiveChallenges` и `allowDuplicatesInHistory` присутствуют в конфигурации, но текущий выбор и активация их не используют. Изменение этих полей не задаёт число одновременных испытаний и не отключает повторы. Два правила включает `double_challenge`.

При загрузке интервал вне допустимого диапазона или нечисловое значение заменяется на 5, отрицательная подготовка — на 0, а предупреждение ограничивается диапазоном от 0 до длительности. Нечисловое предупреждение заменяется на 1 с тем же ограничением диапазона. При ошибке чтения или разбора файла мод использует стандартную конфигурацию и пишет ошибку в лог.
