# Резня: правила и проверки

[Документация](README.md) · [Список испытаний](challenges.md) · [Разработка](development.md)

`blood_tribute` — HARD/GLOBAL. Каждому живому игроку Survival/Adventure нужно лично убить моба за 300 активных серверных тиков (15 секунд при 20 TPS). Мирный моб тоже подходит. Засчитывается последний смертельный удар игрока или попадание его снаряда. Предыдущий атакующий, питомец, ловушка, взрыв, последующий огонь, PvP, стойки для брони и удаление сущности не подходят. Тотем жертвы предотвращает смерть и зачёт. При паре с `budding` смерть родительского моба засчитывается независимо от появления детей.

За 100 тиков (5 секунд) до срока приходит одно предупреждение в чат. При достижении нуля игрок получает 2 HP урона (одно сердце), затем ещё 2 HP каждые 20 активных тиков. Собственный тип урона обходит броню, чары, сопротивление, щит и cooldown, без отбрасывания; поглощение и тотем действуют. Баланс обновлён по запросу пользователя 2026-11-20. Подходящее убийство немедленно прекращает штраф и начинает новый срок 300 тиков. Потерянное здоровье не возвращается.

Офлайн, смерть и Creative/Spectator приостанавливают остаток срока и фазу штрафа. Повторный вход, респаун и смена измерения их сохраняют. Офлайн-время, смена времени суток и пропущенные вызовы не создают очередь урона. Stop/disable/reset и новая активация очищают обязанность; повторная активация того же ID даёт новый срок.

## Настройка в коде

В `src/main/java/com/cursecycle/challenge/impl/BloodTributeChallenge.java`:

- `KILL_INTERVAL_SECONDS = 15` — срок на личное убийство моба.
- `WARNING_SECONDS = 5` — предупреждение за столько секунд до конца срока; держать меньше срока.
- `PENALTY_INTERVAL_SECONDS = 1` — пауза между штрафами.
- `PENALTY_DAMAGE_HP = 2F` — урон за один штраф, 2 HP = одно сердце.

Время задаётся в секундах при 20 TPS, внутри переводится в серверные тики. После изменения констант мод нужно пересобрать. Сообщение после убийства берёт срок из константы; при смене величины/частоты урона также обновить текст правила для игрока и список испытаний. Сохранённые остатки старого трёхминутного срока ограничиваются новым сроком на следующем активном тике; старая фаза штрафа ограничивается новым периодом без сброса долга.

## Реализация

- `BloodTributeChallenge` использует единственный существующий AFTER_DEATH-путь рядом с `BuddingChallenge`. Проверка `MobEntity` отдельная: критерий HostileEntity для почкования сохранён. Общая `DamageHooks.directPlayerAttacker` вынесена из Pacifist без изменения его условий.
- `CurseCycleState.challengeData.blood_tribute.<UUID>` хранит `remaining`, `penaltyRemaining`, `warned`, `overdue`. Сам `challengeData` принадлежит `activationSerial` и очищается существующим `beginActivation`. При каждом изменении вызывается `markDirty`; при штатном сохранении нет дополнительного 20-тикового отставания кеша.
- END_SERVER_TICK после CycleManager обрабатывает снимок списка онлайн-игроков один раз, независимо от повторов ID в GLOBAL/PERSONAL. Неперсистентный guard содержит только объект state, serial и номер последнего тика; очищается при SERVER_STOPPED. Нет кеша жертв, обходов сущностей, чанковых билетов, клиентских Mixin или новых payload.
- Фаза следующего штрафа записывается до вызова damage, который может синхронно убить или телепортировать игрока. Обычный путь подтверждённого урона сохраняет реакции других испытаний. `onPlayerLeave` явно не вызывает `onStop`, чтобы disconnect не прощал долг.

## Автоматический запуск

```powershell
.\gradlew.bat runGametest --offline -I src/gametest/blood-tribute.init.gradle
.\gradlew.bat build --offline
.\gradlew.bat build -x test processGametestResources --offline
```

Предметный init выбирает BloodTribute, Budding, Pacifist и SimonSays; мир — `build/blood-tribute-gametest/run`, XML — `build/blood-tribute-gametest/report.xml`. После него нужно восстановить и сверить штатный список GameTest resources.

12 GameTest проверяют личное/чужое убийство, мирного моба, настоящие melee/arrow/trident, тотем, косвенные источники и PvP, предупреждение/границы/период, защиту/поглощение/тотем игрока, reconnect и офлайн, state NBT, смерть/респаун/измерение/режимы, stop/disable/reset/новую активацию, GLOBAL/PERSONAL и пары. Короткие сценарии меняют сохранённые остатки и сбрасывают только guard между вызовами, не общий серверный счётчик. Отдельный тест проходит полный срок в 300 настоящих серверных тиков и два штрафа, включая скачок времени суток.

## Ручные ограничения

EmbeddedChannel подтверждает содержимое серверных пакетов, но не отрисовку чата и работу двух обычных клиентов. State NBT round-trip в одной JVM не заменяет полный рестарт сервера. Прямой перенос в измерение не заменяет настоящий портал. Обычные клиенты/multiplayer, портал, полный рестарт JVM, полный GameTest-набор и нагрузка/FPS/MSPT в этот этап не входят в автоматическое доказательство и не заявляются проверенными.
