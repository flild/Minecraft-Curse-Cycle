# Проверка slippery_hands

Minecraft 1.21.1, Fabric Loader 0.16.0, Fabric API 0.102.0+1.21.1,
Yarn 1.21.1+build.3, Java 21. Команды активации требуют OP 2.

## Механика и интеграция

`SlipperyHandsChallenge` зарегистрирован через `ModChallenges`: EASY/GLOBAL,
название «Только фонка не хватает», HUD «Тун тун тун тундундун дун дун».
Mixin в `LivingEntity.travel` заменяет результат чтения `Block.getSlipperiness`
для подходящего игрока на 0.98 — коэффициент обычного льда. Это одновременно
согласует ускорение и затухание горизонтальной скорости с ванильным льдом.
Воздушное сопротивление остаётся ванильным, поэтому остановка постепенная.
Фразу ТЗ «трение полностью пропадает» трактуем как ледяное сцепление согласно
правилам и критерию постепенной остановки, а не бесконечное движение без затухания.

Проверка выполняется только на земле, вне воды/лавы, лазания, транспорта и
полёта. Creative и Spectator исключены. Блоки, атрибуты скорости, эффекты зелий
и текущая скорость не перезаписываются. Отключение возвращает исходное
сцепление уже при следующем расчёте движения. Другие сущности не затрагиваются.

Сервер проверяет общий `CurseCycleState` и включённость регистрации. Клиент
использует существующие синхронизированные активные ID в `ClientDataHolder`.
Это GLOBAL-испытание; его ID приходит при входе, активации командой и регулярной
синхронизации цикла. Менеджеры, HUD и протокол не менялись.
Отдельного состояния испытания и сохраняемых модификаторов нет: активный ID
сохраняется в `cursecycle_state` через `PersistentStateManager`, а `CycleManager`
помечает состояние изменённым через запись истории при активации.

## Автоматические проверки

```powershell
.\gradlew.bat build --offline
.\gradlew.bat runGametest --offline
git diff --check
```

JUnit проверяет регистрацию, уникальность ID, русские тексты, EASY/GLOBAL и пул.
`SlipperyHandsGameTest` выполняет реальные `travel` с применённым Mixin:
сравнивает затухание и ускорение на камне с контрольным льдом и обычным камнем,
симулирует секунду ходьбы и секунду движения после отпускания клавиш, проверяет
Creative/Adventure, воздух, воду и полёт. В тестовом серверном игроке разрешён
путь симуляции движения, который у настоящего игрока исполняет его клиент.
Это не проверка реального клиентского ввода или сетевой задержки.

Также проверяются исключение Spectator и транспорта, повторное применение,
поздний вход, переподключение, новый объект после смерти, смена измерения,
двойное испытание, отключение и сохранение стороннего эффекта Speed.
Сохранение проверяется через запись на диск и чтение файла общим
`PersistentStateManager`, затем восстановленный объект подставляется серверу.
Это проверка восстановления состояния, а не полноценный перезапуск процесса.

## Ручные сценарии

1. Выполнить `/fdc list`, `/fdc activate slippery_hands`, `/fdc active`.
   Проверить ID, имя, уведомление «Ноги в масле, катимся колбаской», HUD и правила
   в меню `H`. Для сравнения подготовить длинные дорожки из камня и обычного льда.
2. В Survival идти вперёд одну секунду, отпустить клавишу. На камне должен
   оставаться заметный дрифт с постепенной остановкой, как на ледяной дорожке.
   Проверить разгон, смену направления, поворот, прыжок и приземление, плиты и
   лестницы. Блоки мира должны сохраняться.
3. Повторить в Adventure. Переключиться в Creative, проверить обычную ходьбу
   и полёт; затем Spectator. Вернуться в Survival — скольжение возобновляется.
4. Поплавать, попрыгать в воде, подняться по лестнице, прокатиться на лодке и
   вагонетке; проверить полёт на элитрах. Управление соответствует ванильному.
5. Проверить двух настоящих клиентов: эффект у обоих, включая подключившегося
   после активации. Проверить смерть/респаун, выход/вход и портал в другое измерение.
   Отдельно убедиться в отсутствии рывков и исправлений позиции сервером.
6. Перезапустить сервер при активном испытании, проверить `/fdc active` и инерцию.
   Затем отключить игрока, выполнить `/fdc activate test_easy` и подключить снова:
   сцепление должно быть обычным, старый эффект не возвращается.
7. Выполнить `/fdc activate "double_challenge:slippery_hands,no_sprint"`.
   Скольжение работает, спринт запрещён. Добавить Speed через `/effect`, затем
   выполнить `/fdc activate test_easy`: сцепление возвращается к обычному,
   Speed сохраняется. Проверить уведомление об окончании испытания.

Ручные сценарии требуют настоящего игрового клиента и не считаются пройденными
по результатам серверного GameTest. Полный перезапуск, HUD, ввод и сетевой дрейф
остаются отдельными проверками.

  исключения из пула согласованы с подтверждённой сложностью MEDIUM.
  Новый `SlipperyHandsChallengeTest` прошёл.
- `runGametest --offline`: 4/4 успешно, включая `icePhysicsAndLifecycle`;
  процесс завершился штатно с `BUILD SUCCESSFUL`.
- `git diff --check`, UTF-8 новых файлов и JSON-конфигурации проверены.
- В production JAR присутствуют новая реализация и Mixin; GameTest-классы не включены.
