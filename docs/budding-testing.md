# Почкование: правила и проверки

[Документация](README.md) · [Все испытания](challenges.md) · [Команды](commands.md)

`budding`, MEDIUM, GLOBAL. На месте подтверждённой смерти `MobEntity`, в том числе мирного моба, появляются два ванильных зомби-ребёнка. Причина смерти и убийца значения не имеют. Созданные испытанием существа повторно не почкуются.

## Правила и границы

- Один серверный `ServerLivingEntityEvents.AFTER_DEATH` в `CurseCycleMod`; попытка урона, спасение тотемом, despawn, discard и выгрузка не являются смертью. Повторная доставка той же смерти защищена флагом в самой исходной сущности, без глобального списка UUID.
- GLOBAL проверяется по включённой регистрации и текущему `CurseCycleState`. Смерти во всех измерениях обрабатываются один раз независимо от числа/режима игроков, в том числе без подключённых игроков. Наличие только PERSONAL ID у игрока не включает мировое правило. Это тот же подход к мобам, что у `netherite_mobs` и `low_gravity`: правило не требует личного убийства, близости игрока или Survival-убийцы. Сам игрок, включая Creative/Spectator, источником почкования не является.
- Оба ребёнка создаются в позиции смерти, получают обычную ванильную инициализацию зомби, гарантированный детский возраст и отдельные UUID. Дополнительный всадник/курица не создаются. Нет отложенных появлений, поиска по миру, повторных попыток, chunk tickets или принудительной загрузки чанков. Обычные AI, свет, урон, добыча, экипировка и despawn сохраняются.
- Постоянный boolean `cursecycle:budding_child` хранится в NBT собственной сущности через `BuddingMobMixin`/`BuddingMark`, независимо от активации. Маркер переносится через ванильный `MobEntity.convertTo`, поэтому превращение в утопленника не открывает цепочку. Обычный, в том числе естественно маленький или загруженный, зомби не получает маркер по типу/возрасту.
- При stop/reset/disable прекращаются новые появления. Уже появившиеся дети остаются в мире с прежним маркером. Новая активация, смерть/респаун/выход игрока и смена измерения не снимают маркер: у правила нет привязанной к игроку сессии или очереди, которую нужно переносить/очищать. Незеритовая броня и физика из пары применяются существующими путями рождения/ENTITY_LOAD.

Критерий `MobEntity` включает мирных, нейтральных и враждебных мобов независимо от spawn group и состояния агрессии: животных, жителей, големов, рыб, летучих мышей, тихонь, а также слизней/магмовых кубов, гастов, фантомов, шалкеров и хоглинов. Игроки и стойки для брони не наследуют `MobEntity` и не создают детей. Дракон входит в иерархию мобов, но его отдельный multipart-сценарий смерти не проверен.

## Воспроизводимые команды

Из корня проекта, Java 21:

```powershell
.\gradlew.bat runGametest --offline -I src/gametest/budding.init.gradle
.\gradlew.bat build --offline
.\gradlew.bat build -x test processGametestResources --offline
git diff --check
git diff --cached --check
```

Адресный init использует отдельный мир `build/budding-gametest/run`, XML `build/budding-gametest/report.xml` и четыре entrypoint: Budding, NetheriteMobs, SkeletonHunter, Pacifist. После него нужно восстановить штатные ресурсы командой без init. Production JAR не должен содержать GameTest/пробы. `build` сам GameTest не запускает.

## Ручной сценарий и пределы

В обычном мире: `/fdc activate budding`, убить скелета и корову, дать другому мобу погибнуть от окружения. Каждый должен оставить двух детей; убийство этих детей не создаёт новых. Проверить обычного маленького зомби, жителя, рыбу, пару `double_challenge:budding,netherite_mobs`, затем переключиться на другое испытание: дети остаются, новые не появляются. Сохранить детей в выгруженном чанке, полностью перезапустить сервер, снова включить правило и убедиться, что цепочки нет; повторить после превращения ребёнка в утопленника.

Реальный клиент/отрисовка, два настоящих сетевых клиента, полный рестарт JVM, настоящий цикл записи/выгрузки/чтения файла чанка, портал и измерения нагрузки/FPS/MSPT не заменяются NBT/серверными GameTest в одной JVM. Клиентских Mixin и новых пакетов у R007 нет; отдельная клиентская трансформационная проба не требуется.
