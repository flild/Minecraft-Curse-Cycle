# inverted_mouse — проверка

ТЗ: «Лучше бы вечная тошнота», HARD/GLOBAL. Обе компоненты мышиного
вращения умножаются на −1 после текущей чувствительности, сглаживания,
подзорной трубы и vanilla invertY. Поворот при завершении не откатывается.

## Реализация

- `InvertedMouseChallenge` содержит точные название, краткое описание и правила
  из JSON, зарегистрирован один раз через `ModChallenges`.
- `InvertedMouseMixin` включён только в client-раздел `cursecycle.mixins.json`.
  `@ModifyArgs` меняет два аргумента единственного вызова
  `ClientPlayerEntity.changeLookDirection(DD)` в `Mouse.updateMouse`.
  Место вызова проверено по байткоду Minecraft 1.21.1/Yarn build.3.
- `InvertedMouseInput` на каждом вызове проверяет текущие world/player,
  interactionManager, живой/неудалённый объект, Survival/Adventure и актуальные
  синхронизированные ID. Нет исключений для перспективы, плавания, элитр или
  транспорта. Дубли ID дают одну инверсию одного свежего приращения.
- Используется существующая фильтрация включённых GLOBAL/PERSONAL ID на сервере.
  Временных полей, таймеров, собственных пакетов, ссылок на игрока и NBT нет.
  Сохраняется общая активация в `CurseCycleState`. JOIN/DISCONNECT сбрасывают
  `ClientDataHolder`; новый объект игрока сразу проверяется тем же gate.
- Настройки мыши, перспектива, клавиши, курсор GUI, клики и прокрутка не
  записываются. Абсолютные серверные повороты и остальные вызовы поворота
  проходят своими штатными путями. `inverted_keyboard`, no_sprint и ограничения
  перспективы продолжают работать через существующие перехваты.

## Ручные сценарии — не выполнены

1. Survival, горизонтальный взгляд, известная чувствительность, invertY off:
   сравнить одинаковый физический сдвиг вправо/вверх до/после активации.
   Проверить противоположные yaw/pitch и ту же величину вдали от pitch ±90°.
   Открыть инвентарь/меню: курсор, клики, атака/использование и колесо обычные.
2. Во время активации изменить чувствительность и invertY, включить плавную
   камеру/подзорную трубу. Завершить через `/fdc activate no_sprint`, сменить
   сервер: сохраняются выбранные опции и текущий угол, остаточной инверсии нет.
3. Проверить живые HUD/меню и команды OP 2, естественную активацию циклом,
   все перспективы, плавание, элитры и транспорт. Отдельно пары с
   inverted_keyboard, forced_third_person_front и forced_third_person_rpg.
4. Два живых клиента и поздний вход; Survival → Creative → Spectator →
   Adventure → Survival, смерть/респаун с обоими keepInventory, повторный вход,
   реальные порталы и возврат из End. Инверсия действует на текущий живой
   подходящий объект ровно один раз после синхронизации.
5. `/fdc activate "double_challenge:inverted_mouse,no_sprint"`, затем
   `/fdc activate no_sprint`: мышь возвращается к текущим настройкам,
   запрет спринта сохраняется. Проверить реальные сетевые задержки.
6. Сохранить мир с активным испытанием и полностью перезапустить JVM.
   Повторить после завершения, пока второй игрок офлайн; вернуть игрока.
   Активность соответствует диску, состояние другого сервера не переносится.

Сборка, серверный GameTest и CLIENT-стенд не заменяют эти ручные проверки.
`upside_down_camera` ещё не реализован по очереди; совместимость с его будущим
креном здесь не объявляется проверенной.
