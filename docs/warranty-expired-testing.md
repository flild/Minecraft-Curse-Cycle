# Гарантия закончилась — правила и проверки

[Документация](README.md) · [Все испытания](challenges.md)

`warranty_expired`, MEDIUM, GLOBAL. Обычный расход прочности используемых предметов и надетой брони умножается на **3 до применения чар Прочности (Unbreaking)**. Это множитель входного расхода за действие, поэтому фактическая потеря прочности зачарованного предмета остаётся случайной. Добыча, удар, выпуск стрелы, блокирование щитом и повреждение брони используют прежние ванильные пути. Остальные обычные применения предметов с прочностью проходят через тот же серверный метод.

Нет таймера порчи инвентаря. Предметы в запасе, на земле, бездействующий инструмент и броня без повреждений не получают собственного пассивного износа. Починка (Mending), отрицательный расход/ремонт и неразрушимость остаются ванильными. Creative исключён; для Spectator множитель не применяется. Survival/Adventure, GLOBAL/PERSONAL и двойное испытание используют существующий `ChallengeActivity`; повторный ID не добавляет второго множителя. Предметы мобов и вызовы без игрока не затрагиваются.

## Реализация

- `WarrantyExpiredChallenge` задаёт метаданные и коэффициент, один раз зарегистрирован в `ModChallenges`.
- `WarrantyExpiredItemStackMixin` меняет только положительный аргумент серверной перегрузки `ItemStack.damage(int, ServerWorld, ServerPlayerEntity, Consumer<Item>)` на входе. Точные сигнатуры и порядок проверены локальным `javap` для Minecraft 1.21.1 / Yarn 1.21.1+build.3. `damage(int, LivingEntity, EquipmentSlot)` делегирует ей; перегрузка с преобразованием предмета делегирует пути экипировки.
- Умножение выполняется один раз, до `EnchantmentHelper.getItemDamage`. Нет повторного `damage`, собственной рекурсии, decrement или break-callback; ваниль сама выполняет проверку damageability/Creative, чары, статистику и поломку. Для большого аргумента используются long и ограничение перед сложением с текущим повреждением.
- `setDamage`, Mending и сохранение предмета не перехватываются. Нет NBT испытания, кеша владельцев, нового сетевого протокола, тика или клиентского кода.
- Stop/disable/reset/новая активация и смена PersistentState действуют на следующий расход. Смерть/респаун, disconnect/join и измерение не требуют очистки сессий. Уже потраченная прочность не возвращается и сохраняется обычным NBT предмета.

## Свежие автоматические проверки

Дата: 2026-11-19, Europe/Moscow. Из корня проекта:

```powershell
.\gradlew.bat runGametest --offline -I src/gametest/warranty-expired.init.gradle
.\gradlew.bat build processGametestResources --offline
git diff --check
git diff --cached --check
```

Адресный GameTest: **46/46**, из них **9/9 WarrantyExpired**, NetheriteMobs 6/6, Pacifist 8/8, AttackRecoil 8/8, DamageSlotDrop 8/8, DamageTeleport 7/7. Сервер штатно завершён. XML: `build/warranty-expired-gametest/report.xml`; окончательный лог: `build/warranty-gametest-final-console.log`.

Новые сценарии доказывают:

- Настоящие `interactionManager.tryBreakBlock`, `PlayerEntity.attack` и полный выпуск стрелы: каждый обычный расход 1 становится 3; добытый блок/урон/расход стрелы подтверждены.
- Настоящий блок щитом входящего урона 4: обычный износ 5 становится 15, здоровье сохранено. Настоящий входящий удар 8 по четырём надетым частям брони: каждая теряет 6 вместо 2, защита/потеря здоровья подтверждены.
- 32 фиксированных seed для инструмента и брони с Unbreaking III: результат каждого вызова точно совпадает с ванильным `getItemDamage` от утроенного входа; защита чар реально срабатывает.
- Настоящий подбор XP-сферы с Mending: 7 XP чинят 14 прочности; отрицательный расход −2 чинит ровно 2, нулевой ничего не меняет.
- Неразрушимость, обычные блоки, крупный расход без переполнения; поломка с ровно одним callback и одной ванильной статистикой сломанного предмета через перегрузку экипировки.
- Независимые владельцы/PERSONAL, GLOBAL вместе с PERSONAL и двойным испытанием, Adventure, Creative/Spectator, выключенный ID; предмет моба и вызов без игрока — контроль без множителя.
- NBT активного PersistentState и его замена в менеджере, reset/новая активация/stop, NBT повреждённого предмета; смерть/респаун, Fabric disconnect/join и прямой серверный переход в Nether и обратно.
- **100 настоящих серверных тиков**: бездействующий предмет в руке, запасное оружие, надетая броня и выпавший предмет не изнашиваются.

Первые два прогона обнаружили ошибки только новых fixtures: выключенный PvP, использование старой ссылки при замене PersistentState и неполный `ServerPlayerEntity.tick` вместо `playerTick` для атрибутов экипировки. Они исправлены в тестах; окончательный прогон выше успешен. Производственная логика износа не подгонялась под эти ожидания.

Полная `build processGametestResources --offline` успешна: **199/199 JUnit**, без ошибок/пропусков. Лог: `build/warranty-build-final-console.log`, XML: `build/test-results/test/`. Восстановлены и сверены все **55 штатных entrypoint** GameTest. Реестр и список совпадают: **61/61 ID**, 54 обычных + 1 специальное + 6 тестовых. Production JAR `build/libs/curse-cycle-1.0.5.jar` содержит новый класс/Mixin и UTF-8-правила, без GameTest/проб. JSON, локальные ссылки, UTF-8 и diff проверены.

## Ручные пределы

Не запускались полный набор GameTest, обычный клиент, реальные сетевые клиенты/анимация поломки и HUD прочности, настоящий портал, полный рестарт JVM и нагрузка. EmbeddedChannel-подключения, прямой teleport и NBT round-trip в одной JVM не заменяют эти проверки. Клиентская проба не требуется для серверной перегрузки: клиентские обработчики и Mixins не менялись.

Для ручного прогона: `/fdc activate warranty_expired`; проверить добычу, удар, лук, щит и броню без чар и с Unbreaking/Mending. Переключить на другое испытание и убедиться, что новые действия тратят обычную прочность, старая потеря не возвращается. Проверить поведение двумя настоящими клиентами и после перезапуска сервера.
